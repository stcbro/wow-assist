## 内置注入器取代 VanillaFixes.exe（v3.10，01:31 版，最终达成用户目标）
**目标**：游戏根目录自始至终不再出现 VanillaFixes.exe。

### 逆向结论（决定性证据）
- VanillaFixes.exe = 引信，硬编码注入 `VfPatcher.dll` + `nampower.dll`（CreateProcessW→VirtualAllocEx→WriteProcessMemory→CreateRemoteThread(LoadLibraryW)→ResumeThread）。
- VfPatcher.dll = **MinHook 框架 + 加载器**：导出 MH_CreateHook/CreateTrampolineFunction/SignatureSearch/LoaderParseConfig/InitAdditionalDLLs/RemoteLoadLibrary，内含 `dlls.txt` 字符串与 "Make sure you have a compatible game client (1.6.1-1.12.1)" 校验。
- **关键发现**：`D:/game/twmoa_1181/twloader.dll`（PDB 路径暴露为 TurtleLoader，乌龟服官方加载器）**自己会读 dlls.txt 并 LoadLibrary 列表里的 DLL**，日志写在 `Logs\twloader.log`。
- **铁证**（用户 00:35 会话留下的 twloader.log）：7 个模组 DLL 均为 `Loaded:`，只有 VfPatcher.dll 与 nampower.dll 是 `Already loaded` —— 即**只有这两个必须在游戏初始化极早期由外部注入**，VanillaFixes 的全部价值仅此而已。

### 实测踩坑（勿回退）
1. **挂起态注入必失败**：CREATE_SUSPENDED 时模块列表为空（用户态未初始化），LoadLibraryW 返回 0 且 GetLastError=0。用带 `0xDEADBEEF` magic 的 shellcode 验证过——代码确实执行，是 Windows loader 拒绝加载。→ 必须**正常启动、等 kernel32 出现**后再注入。
2. **shellcode 诊断路径本身不可靠**：连 VERSION.dll 都报句柄 0 / 错误 0。判断成败**只能查目标进程模块列表**，不能信线程退出码。
3. **LoadLibraryW 地址** = 目标进程内 32 位 kernel32 基址 + RVA(解析 SysWOW64\kernel32.dll 导出表)。系统 DLL 基址全机一致（实测 0x76370000），RVA=0x1f640。
4. **VirtualAllocEx 返回值必须按无符号处理**（>=0x80000000 会被当负数，传给 CreateRemoteThread 符号扩展成无效地址）。
5. VfPatcher/nampower 注入**非游戏进程会失败**（属预期，它们要 WoW 环境）；对照实验中系统 DLL VERSION.dll 注入成功、fmod.dll 也失败，说明非系统 DLL 在此环境普遍加载失败，不代表代码有问题。

### 实现（addon_helper.py）
- 新增 `_win32()/_STARTUPINFOW/_PROCESS_INFORMATION/_pe_export_rva/_syswow_kernel32/_modules32/_proc_alive/_inject_dll/_inject_after_launch`，删除 `_bundled_loader/_ensure_loader/_remove_loader/_wait_game_exit_and_cleanup/LOADER_NAME`。
- `launch_game`：同步 CreateProcessW 启动 WoW.exe（cwd=游戏根，CREATE_NO_WINDOW）→ 拿 pid → **后台线程**跑 `_inject_after_launch`（等 kernel32 → 解析 RVA → 注入 VfPatcher/nampower，失败重试至 20s）。界面 0.09s 即返回，不卡顿。
- 容错：注入失败**不阻断**，twloader 会按 dlls.txt 兜底加载全部模组；进程已退出时 0.03s 立即结束（不再白等 20s）；全程日志落 run.log `[模组]` 行。
- 装模组/本地导入**不再拷贝** VanillaFixes.exe；老版本残留文件自动清理（清理还原路径保留删除逻辑）。
- 打包已移除 `--add-data "VanillaFixes.exe;."`，构建目录副本已删除。

### 验证
- 端到端（临时游戏根 + 替身 exe）：launch_game 0.09s 返回，**游戏根目录无 VanillaFixes.exe** ✓
- 场景1（进程存活）：完整后台注入流程跑通，日志正确写入 ✓；场景2（进程已退出）：0.03s 立即结束 ✓

### 踩坑记录（重要）
1. **环境变量名含 `PASS` 会被过滤成 None** —— 之前多次"登录失败"实为密码根本没传进去（填了空密码），不是密码被改。必须用 `LZ_PW`（脚本兼容 LZ_KEY/LZ_SECRET）。
2. **Playwright 的 Edge 路径必须用 Windows 形式** `C:/Program Files (x86)/...`；写 `/c/...` 会被解析成 `\c\...` 找不到。
3. **登录流程**：必须先访问 `www.lanzou.com` 再点「登录」进 `up.woozooo.com/account.php?action=login`；直接跳 accounts 登录页会因缺 formhash 静默失败。
4. **蓝奏云同名文件不覆盖、会并存** —— 每次上传同名 exe 多一份，必须 `--prune`（保留 DOM 首行=最新）。
5. **上传后列表异步刷新** —— prune 前必须强制刷新列表，否则读到旧列表漏删副本。
6. **行结构**：文件行 = `div.f_tb`（id 形如 `f326653283`）；`a.f_selb` = "..."菜单（下载/删除文件），`a.f_sela` = 分享/属性面板（外链分享地址/自定义外链/密码设置/修改资料/短网址）。短网址与自定义外链的 AJAX 长期"获取中..."读不到值，**放弃自动取分享链接**（易误触删除），改走"把 exe 放进已有分享链接的文件夹"。
