# WowAssist UI/UX 评审与优化建议

> 评审范围：ui.html 全部 7 个页面（首页/服务器/模组/插件/字体/下载/更新日志）+ 通用组件。
> 视角：面向「零编程、只想打游戏」的目标用户，按 信息架构 → 下载页（重点）→ 各页 → 通用组件 的顺序分析，末尾给优先级排序。

---

## 〇、总体评价

**做得好的**：暗色侧栏单页架构清晰；三资源页（模组/插件/字体）结构统一、勾选即保存的心智模型一致；确认弹窗（琥珀警示条）比原生 confirm 好得多；日志带时间戳、最新在上符合直觉。

**核心问题一句话**：**页面按"开发功能"划分，而不是按"用户任务"划分**——最典型就是下载页，把「下载资源」这一个用户任务和 4 种「更新源配置」的开发细节平铺在同一个页面里。首页则承担了太多职责（信息+更新+进度+日志），次要信息把主任务（配置→启动）淹没了。

---

## 一、信息架构（页面划分）

### 问题 1：7 个一级页面，其中 2 个撑不起来
- **「服务器」页**：只有一张卡 4 行信息（版本/连线地址）。为这点内容占用一个一级导航不值得。且用户只用一个服，这页几乎永远不用点开。
- **「更新日志」页顶部放「关于 WowAssist」**：关于信息 ≠ 更新日志。侧栏品牌处已有版本号，这里重复。

**建议**：
- 「服务器」降级为首页右侧或底部的一张信息卡（版本 + 连线地址两行即可），侧栏减到 6 项。
- 「关于」移到侧栏底部（点弹小窗）或更新日志页最底部收进 `<details>` 折叠。

### 问题 2：导航与用户任务的对应关系
用户的真实任务链是：**选路径 → 下载（缺则自动）→ 勾选 → 配置 → 启动**。当前导航是按"资源类型"分页（模组/插件/字体），这没问题；但「下载」页混入了更新源配置，「更新日志」混入了关于页——**每页应只有一个主题**。

---

## 二、下载页（重点，用户点名）

当前页面从上到下 5 张卡片：资源管理（含缓存设置+3 按钮）→ 资源地址 → 备用直链 → 更新清单 → 应用更新。问题逐条：

### 2.1 主任务被淹没（P0）
- 视觉动线：3 张资源卡 → 缓存目录 → 缓存开关 → 最近使用时间 → **然后才是一键下载按钮**。用户最想做的「下载」要滚过 200px+ 的次要信息才看到。
- **改法**：把「⬇ 一键下载全部资源」提到页面第一行（大按钮），或直接放进 3 张资源卡的同一行。缓存管理整体后移。

### 2.2 「高级配置」和「日常操作」混排（P0）
「资源地址」「备用直链」「更新清单」三张卡全是**作者/排障用的更新源配置**，99% 的用户永远不用碰，却占了下载页一半的面积。而且三个蓝奏云链接输入框长得一模一样，用户分不清哪个管什么、为什么有三个。

**改法**：三张卡合并为一张「高级设置」，用 `<details>` 折叠（默认收起），内部再加一行小字说明各自用途：
```
▸ 高级设置（更新源配置，一般不用改）
   ├ 资源地址：资源包从哪个蓝奏云文件夹下载（内置默认可用）
   ├ 备用直链：蓝奏云不稳时的高速直链（COS/OSS/GitHub）
   └ 更新清单：插件增量更新的 manifest 链接
```

### 2.3 开发实现细节泄露（P1）
- 「应用更新」卡片大段解释"该文件夹里需放 release_manifest.txt（蓝奏云拒收 .json，故用 .txt，内容仍是 JSON）"——这是分发机制的实现细节，对用户零价值。
- **改法**：删掉机制解释，只留用户视角的一句话："发现新版本会自动下载并重启程序"。更新源配置框同理：普通用户只需要「自动检查更新」开关 + 状态行，配置输入框也应收进高级折叠。

### 2.4 资源卡信息密度低（P1）
每张卡一整行只传达：名字 + 状态点 + 分卷数 + 下载按钮。**改法**：三张卡改紧凑三列并排（980 宽足够），或一张小表：
```
资源     状态        大小/分卷    最近使用     操作
模组     ● 已就绪    9 个        3 天前       [✓已缓存]
插件     ● 待下载    4 个分卷    从未使用     [⬇下载]
字体     ● 已就绪    9 个        10-31        [✓已缓存]
```
顺带把现在单独一行的「最后使用时间」合并进来（现在是三行小字占一块）。

### 2.5 按钮语义重复（P1）
「⬇ 一键下载全部资源」和「🔄 检查插件更新」用户分不清区别（实际一个是全量下载、一个是 manifest 增量）。**改法**：改名「检查插件更新」→「增量更新插件」，并加 tooltip 一句话说明；或把增量更新收进插件资源卡内作为次级操作。

### 2.6 颜色语义滥用（P2）
「保存设置」（缓存）用了 amber 高亮色——三级操作不配主警示色。改普通 `btn` 即可，amber 留给「需要用户注意」的场景。

### 2.7 进度反馈（P2）
下载进度只有一根条+一行 msg。建议加：当前文件名 / 第 N 个文件 / 速度 / 已用空间变化，下载 4 个分卷时用户需要知道在动。

## 三、首页

### 3.1 按钮颜色语义冲突（P1）
「▶ 启动游戏」默认蓝、配置完成后**变琥珀金**；但琥珀金同时是「清理还原」「确认弹窗」的警示色。同一个颜色表达"就绪✓"和"危险⚠"两种语义。
**改法**：就绪态直接用 accent 绿（与"✓已装"状态一致），amber 全站只用于警告。

### 3.2 状态行抢视觉（P2）
「资源 待检测 模组 待检测 插件 待检测 字体 待检测」一行 15px 粗体，未配置时全是"待检测"——没有信息量的状态占据了最重的视觉权重。
**改法**：未检测状态收成一行小字"点「配置组件」自动检测资源与安装状态"；检测结果出来再升级为彩色状态行。

### 3.3 纵向堆叠过长（P2）
信息行 → 更新横幅 → 检查更新 → 状态行 → 三按钮 → 进度条 → 日志（420px）。首屏看不见操作按钮的风险存在。
**改法**：日志区默认高度降到 ~260px；「检查更新」小按钮可并入更新横幅（无更新时显示"已是最新 vX"一行小字即可，去掉独立按钮）。

### 3.4 信息行内容混杂（P3）
「当前客户端（1.18）」与「已装插件（150 个）」并排——一个是环境、一个是数量。建议首页信息区分两组：**环境**（客户端/服务器/地址）与 **状态**（资源/模组/插件/字体），与按钮区就近。

## 四、模组 / 插件 / 字体页

### 4.1 插件页缺搜索/筛选（P0，三页里最痛的一点）
150 个插件一张平表，只能滚动肉眼找。已有「分类」数据（PLUGIN_INFO 的 c 字段）但没利用。
**改法**：表头上方加：搜索框（匹配名称/中文名）+ 分类下拉（全部/必需依赖/职业/界面/增强/商业/辅助…）+ 状态过滤（全部/已安装/未安装）。纯前端过滤即可，十几行 JS。

### 4.2 危险按钮位置（P1）
每页顶部：「装入」（primary 绿）和「移除」（danger 红）并列且在最前。误触风险 + 视觉上"移除"权重过高。
**改法**：危险操作放按钮行最右，且用 `btn danger`（描边）而非实心；或收进「···更多」菜单。三页统一。

### 4.3 「刷新」按钮可以去掉（P2）
每次进入页面自动加载，操作后也自动刷新——手动刷新几乎无用。去掉可让按钮行更干净。（保留也无害，低优先级。）

### 4.4 模组页类型列重复（P3）
名称旁有 SUNI 描边 tag，「类型」列又是「SUNI 增强」tag——同屏重复。删一列即可（类型列信息本来就和 tag 重复）。

### 4.5 日志区位置不一致（P3）
模组页 `#dll-log` 在卡片外，字体页 `#f-log` 在卡片内。统一放卡片内（视觉归属更清晰）。

## 五、更新日志页

- **P2**：整页一张超长卡片，无折叠。建议：每版本一个 `<details>`，最近 2~3 版默认展开，更早的默认收起（首行就是 kv 标题行，体验连续）。
- 「关于」卡片按 §一 建议移走。

## 六、通用组件

### 6.1 toast 无类型区分（P1）
成功/失败同一个黑底样式，2.2 秒消失。**改法**：`toast(msg, type)`——成功绿边/失败红边/警告琥珀边；失败类时长 4s 或带关闭钮。下载失败这类关键反馈尤其需要。

### 6.2 确认弹窗的按钮色（P2）
所有确认的「确定」都是琥珀。清理还原/移除类应红（danger），更新确认保持琥珀。小改一行 CSS 类即可。

### 6.3 输入焦点态缺失（P3）
input 无 `:focus` 样式（只有浏览器默认 outline）。加一条 `input:focus{border-color:var(--accent2)}` 与 hover 呼应。

## 七、优先级总表

| 优先级 | 改动 | 位置 | 工作量 |
|---|---|---|---|
| **P0** | 下载页重组：主按钮前置、高级配置折叠、删开发向文案 | 下载页 | 中 |
| **P0** | 插件页搜索+分类/状态筛选 | 插件页 | 小 |
| **P1** | 服务器页并入首页（导航 7→6 项） | 首页/服务器 | 小 |
| **P1** | 资源卡改紧凑表/三列，合并"最近使用" | 下载页 | 小 |
| **P1** | 按钮色语义：就绪=绿、amber 只表警示 | 首页/下载页 | 小 |
| **P1** | 危险「移除」按钮右置+弱化（三页统一） | 模组/插件/字体 | 小 |
| **P1** | toast 分类型（成功/失败/警告） | 全局 | 小 |
| **P2** | 状态行"待检测"降权、检查更新并入横幅 | 首页 | 小 |
| **P2** | 更新日志按版本折叠 | 更新日志页 | 小 |
| **P2** | 确认弹窗危险类用红色确定钮 | 全局 | 小 |
| **P2** | 下载进度加文件名/速度明细 | 下载页 | 小 |
| **P3** | 「刷新」按钮移除、模组类型列去重、日志区位置统一、input focus 样式 | 各处 | 极小 |

## 八、改版示意（下载页目标形态）

```
┌─ 下载 ────────────────────────────────────────┐
│ [⬇ 一键下载全部资源]   [增量更新插件]  状态提示… │
│                                                │
│ 资源     状态       分卷      最近使用   操作   │
│ 模组     ● 已就绪   1        3 天前    [✓已缓存]│
│ 插件     ● 待下载   4        从未使用  [⬇下载] │
│ 字体     ● 已就绪   1        10-31     [✓已缓存]│
│                                                │
│ 缓存目录 D:\...\resources（已用 512 MB）        │
│ ▸ 缓存自动清理设置（默认开启，30 天未用即清）     │
│ ─────────────────────────────────────────────  │
│ ▸ 高级设置（更新源配置，一般不用改）              │
│ ▸ 应用更新（自动检查新版本）  [开关●] 已是最新 v3.23│
└────────────────────────────────────────────────┘
```

一句话总结：**让每个页面回答一个用户问题**——下载页回答"我的资源齐不齐、怎么下"，首页回答"能不能开打了"，资源页回答"装哪些"。次要配置全部折叠、危险操作全部弱化、实现细节全部删掉。
